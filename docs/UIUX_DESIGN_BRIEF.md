# MeetCopilot — 前端 UI/UX 設計需求規格（交付 Claude Design 用）

> 用途：把本檔連同截圖交給 Claude Design（或任何設計代理），產出可直接落地到本 repo 的前端設計。

## 一、產品是什麼（30 秒版）

B2B 銷售平台：**CRM＋公司研究引擎**為核心，餵三個消費端——
1. **DynamicSlide**：會前用 wizard 生成簡報、會中依對話即時「追加」簡報頁（經報告者批准）。
2. **會中副駕**：開會時即時給報告者補充資訊（HUD 第二畫面）。
3. **語音模擬訓練**：AI 用 CRM 資料扮演客戶，跟業務做語音對練。
另有獨立的**平台管理後台**（apps/admin，token 花費／帳號／job 監控／健康，管理者專用）。

使用者＝中文為主的 B2B 銷售團隊；**UI 語言 zh-TW 為主、en 為輔**（next-intl，`[locale]` 路由前綴）。

## 二、技術與硬性約束（設計必須在框內）

1. **技術棧**：Next.js 15 App Router＋TypeScript＋**純 CSS（CSS 變數 design tokens）＋自繪 SVG 圖表**。不引 Tailwind／UI 框架／圖表庫（repo 慣例，勿破例）。
2. **既有視覺基調**：深色系（CRM 區已有完整 token，審測評價「設計不差」）。設計應**擴充並統一**現有 token，而非另起爐灶。已知 token 債：卡片圓角出現 5 種值、兩種未 token 化的卡片底色、死 token `--mc-surface-2`、重複 keyframe——設計系統要一次收斂。
3. **三大產品不變量在 UI 的表現**（違反＝直接退件）：
   - **I1**：會中只能「追加」簡報頁；已播（committed）頁在 UI 上不可出現任何編輯入口；pending 與 committed 要有清楚視覺區分。
   - **I2**：AI 建議頁必須經報告者「批准」才進 live deck——批准卡是核心互動，要醒目、可一鍵接受/編輯/拒絕。
   - **I3**：**present（被分享的簡報畫面）絕不可出現任何副駕/HUD 元素或詞彙**。present 視圖只有簡報本身＋中性的連線狀態。
   - admin 後台另有 A1–A3（不洩秘密、read-mostly），見 `docs/ADMIN_CONTRACT.md`。
4. **API 形狀不可改**：頁面所需資料以 `docs/API_CONTRACT.md`＋`docs/ADMIN_CONTRACT.md` 為準；設計可以提「需要新端點」的建議清單，但不得假設既有端點回傳不存在的欄位。
5. **RWD**：產品端 desktop-first（1440 主、1280 最低），行動裝置**至少不破版**（審測抓到行動版頂欄徽章直排三行、tab 溢出、stepper 擠——都要在設計中解）。admin 端 1280+ 即可。

## 三、資訊架構（現況問題＋目標）

**現況問題（審測實錘）**：
- 頂欄只有 crm/studio/train 三入口；**設定/團隊頁是孤兒**（無入口）；會議入口不明顯；首頁還是開發佔位頁（且公開曝露 present/copilot/hud 連結——I3 縱深風險）。
- 無語言切換器；`/en` 幾乎沒翻譯。
- 每頁 `<title>` 空、favicon 404、404 頁是 Next 原生英文頁。

**目標 IA**（設計輸出要含導覽全案）：
```
登入前：/login /register（＋/invite 接受頁）
登入後（頂欄或側欄）：
├─ 首頁/儀表板（今天的會議、最近 deck、待辦研究——取代佔位頁）
├─ CRM（公司清單 → 公司詳情 8 tabs＋研究面板）
├─ 簡報（deck 清單 → wizard 三步 → deck 檢視/編輯）
├─ 會議（會議清單/建立 → 三視圖入口：capture/present/HUD，含「怎麼開」的引導）
├─ 訓練（persona 選擇 → 語音對練）
└─ 設定（團隊成員/邀請、org 資訊、用量 /usage）
全域：語言切換器（zh-TW/en）、使用者選單（登出）、每頁 title/favicon、主題化 404/error 頁
```

## 四、逐頁需求（用途／主要狀態／已知壞點）

每頁都要交：預設態＋空狀態＋載入態＋錯誤態。審測抓到大量「只有 happy path」的頁。

### 4.1 Auth（第一印象重災區，優先重設計）
- 登入/註冊：目前輸入框是瀏覽器原生白底貼在深色卡上（「像半成品」）。要完整表單樣式、錯誤訊息中文人話（欄位級＋全域級）、loading 態、Google 登入按鈕併排的層級關係。
- /invite 接受頁（快修中已補）：邀請資訊卡＋接受 CTA＋token 失效的友善終態。

### 4.2 CRM（基礎好，做增量）
- 公司清單：搜尋/新增/空狀態已可用；設計統一卡片與表格樣式即可。
- 公司詳情 8 tabs：行動版 tab 溢出要解（scrollable tabs 或 more 選單）；「原文＋🌐中文簡介」並排格式可再優化；provenance 徽章（人工 vs 爬蟲）是亮點、保留並強化。
- 研究面板：三模式選擇（quick/detailed/deep）＋成本時間提示（快修中）；**進行中**要有階段回饋；**完成**要有持久的完成卡＋來源清單（快修中）；失敗要有人話原因＋重試。

### 4.3 簡報線（流程通，磨質感）
- deck 清單、wizard 三步（objective 下拉、欄位全中文標籤、匯入錯誤人話化——快修中）。
- 生成中：階段提示＋耗時＋預估（快修中）；設計可加骨架預覽。
- deck 檢視：六模板渲染 4/5 分，重點是 **stats 模板數字排版**與 **image-full 無圖態**；生圖按鈕要帶成本/時間預警（快修中）。
- 匯出 pptx：已可用。

### 4.4 會議三視圖（P0 重災區，快修中打底、設計要給完整方案）
- **連線狀態機是靈魂**：連線中/已連線/失敗（原因＋重試鈕）/重連中（次數上限）→ 每個視圖都要有一致的狀態元件；絕不允許「未連線但畫面看似正常」。
- capture（擷取端）：權限請求前的說明、音量表、zero-track 警告。
- present（分享端）：**只有簡報＋中性狀態**（I3）；「會議尚未開始」「無 deck」「連線失敗」三終態。
- HUD（副駕端）：資訊卡流（訊號→建議卡）、批准互動（I2 核心：接受/編輯/拒絕）、空狀態（「聆聽中，尚無建議」要跟「未連線」清楚區分）。
- 會議建立/開始的引導流程（審測發現「建完會議不知道下一步」）。

### 4.5 訓練
- persona 選擇：無 verified CRM 資料時的空狀態要教使用者去哪補資料。
- 對練前確認 dialog（麥克風＋計費提示，快修中）；對練中的音訊視覺回饋＋結束/評分呈現（四維評分卡）。

### 4.6 Admin 後台（apps/admin，已按 ADMIN_CONTRACT 建骨架，設計做視覺層）
六頁：登入／總覽（KPI 卡＋sparkline＋折線＋圓環）／花費（範圍＋groupBy＋明細 drawer）／組織（含詳情、停權二次確認）／Jobs（統計＋篩選表格）／健康。桌面 1280+，乾淨專業工具風，與產品端共享 token 但可更「密」（資料密度優先）。

## 五、全域設計系統要求

1. **Token 全面收斂**：色彩（表面/文字/強調/語意四組）、圓角（≤3 檔）、間距刻度、字級層級（目前層級混亂）、陰影。深色為主；亮色可列 v2。
2. **狀態回饋規範**：所有非同步操作必有 loading（>300ms 即顯示）；錯誤一律人話中文＋可行動建議；成功用 toast＋（必要時）持久卡。
3. **元件庫清單**（設計要逐一交付樣式）：按鈕（主/次/危險/文字）、輸入框全家（含深色適配）、卡片、表格（排序/分頁）、tabs（含行動 overflow）、badge/StatusBadge、modal/confirm dialog、toast、空狀態插圖風格、骨架屏、連線狀態元件、進度/階段指示器。
4. **i18n**：所有文案走 next-intl key；設計稿雙語都要能容納（en 比 zh 長 30% 的按鈕不能爆）。
5. **每頁 metadata**：title 規則「頁名 · MeetCopilot」、favicon、OG 基本款。

## 六、優先序（給設計的排序建議）

1. **P0 級體驗**：Auth 頁全套＋全域導覽/IA（含首頁儀表板取代佔位頁）＋連線狀態元件系統。
2. 會議三視圖＋HUD 批准卡（產品核心差異化）。
3. 研究面板進行中/完成態＋wizard 生成中體驗。
4. 設計系統收斂（token/元件庫）＋404/error/empty 全家。
5. Admin 六頁視覺層。
